# Grill Diploma — аудит дипломної проти правил оформлення

Перевіряє згенерований документ кваліфікаційної роботи проти офіційних правил
оформлення (`docs/diploma-rules/RULES.md`). Мета — не "переглянути", а
**прискіпливо знайти кожне порушення** і дати конкретний фікс із посиланням на пункт правил.

## Вхід

Аргумент — шлях до документа для перевірки (`.md`, `.tex`, `.txt`, `.docx`, `.pdf`).
Якщо аргумент не задано — запитати у користувача який файл/розділ перевіряти
(не вгадувати). Якщо вказано "повна робота" — перевіряти структуру цілком.

## Процедура

### 1. Завантажити еталон
- Прочитати `docs/diploma-rules/RULES.md` повністю (це джерело істини).
- За потреби уточнення формулювання — звіритися з `docs/diploma-rules/pravyla-raw.txt`
  (grep по номеру пункту) або `pravyla-proj.pdf`.
- Зразки структурних елементів — `docs/diploma-rules/appendices/*.docx` (титул, анотація, зміст, вступ).

### 2. Витягнути перевірюваний документ
- `.docx` → `unzip -p <file> word/document.xml` + витяг тексту, або python-docx, щоб дістати
  шрифти/розміри/інтервали де можливо.
- `.pdf` → `python3 -c "from pdfminer.high_level import extract_text; ..."`.
- `.md`/`.tex`/`.txt` → прочитати напряму.
- Зафіксувати, що **піддається машинній перевірці** (структура, нумерація, формулювання,
  порядок елементів, текстові патерни) і що **ні** (точні поля в мм, кеглі, інтервали у
  розмітці без стилів) — останнє позначати як "потребує ручної перевірки в редакторі".

### 3. Прогнати чек-лист (кожна категорія = окремий прохід)

Перевіряти **усі** застосовні категорії з `RULES.md`:

1. **Загальні параметри** (§1) — шрифт TNR 14, інтервал 1,5, поля 25/10/20/20,
   абзац 1,25 см, відсутність порожніх рядків поза дозволеними, відсутність висячих рядків.
2. **Структура й порядок елементів** (§2.1) — наявність і послідовність: титул → анотація
   укр → ABSTRACT → зміст → перелік позначень → вступ → розділи → загальні висновки →
   список джерел → додатки; кожен з нової сторінки.
3. **Титульний аркуш** (§2.2) — усі 24 блоки, правильні кеглі (12/14/16 пт), курсиви,
   великі літери прізвищ, дужки групи, тире міста–року.
4. **Заголовки структурних елементів** (§2.3) — великими, напівжирні, по центру, без
   крапки, без переносів; розділи без слова «розділ»; додатки — дозволені літери.
5. **Анотація** (§2.4) — бібліоопис, обсяг, результати, `Ключові слова:`/`Keywords:` курсивом.
6. **Зміст** (§2.5) — повнота позицій, відступи 0/0,5/1,25 см, крапки-лідери, номери сторінок.
7. **Вступ** (§2.6) — актуальність/мета і задачі/об’єкт/предмет/апробація, назви напівжирні з крапкою.
8. **Нумерація підрозділів/пунктів/підпунктів** (§3.1–3.3) — формат `1.1`, `1.1.1`,
   без крапки після номера; крапка в кінці заголовка пункту, без — у підрозділі.
9. **Інтервали заголовків** (§3.4) — обов’язкові/заборонені порожні рядки; заборона тексту
   між заголовком розділу і першим підрозділом; заголовок не на останньому рядку сторінки.
10. **Рисунки** (§4) — підпис `Рисунок N – назва` (мала літера), нумерація в межах розділу,
    посилання в тексті, джерело в назві, написи ≥10 пт, порожні рядки навколо.
11. **Таблиці** (§5) — `Таблиця N – назва`, нумерація, шрифти 8–14/12–14, посилання,
    «Продовження/Кінець таблиці» при перенесенні, заборона діагоналей, прочерки.
12. **Сценарії/лістинги** (§6) — нумерація, заголовки, роздільна лінія 0,25 пт,
    Courier New 10 пт для коду, посилання в тексті.
13. **Переліки** (§7) — двокрапка перед, `;` між позиціями, `.` остання, схема
    цифра→літера→тире, права дужка `)`.
14. **Примітки** (§8) — 12 пт, інтервал 1,0, `Примітка.`/`Примітка 1.`, з крапкою.
15. **Формули** (§9) — окремий рядок по центру, нумерація `(розділ.n)` праворуч, блок «де»
    з відступом 1,25 см, накреслення змінних/векторів/одиниць, без сканованих формул,
    діапазони «від … до …».
16. **Посилання** (§10) — квадратні дужки для джерел, `рис.`/`табл.`/`(сценарій)`/`(лістинг)`,
    формули в дужках, цитати в лапках з посиланням і сторінками.
17. **Список джерел** (§11) — перед додатками, порядок першої згадки, ДСТУ 8302:2015.
18. **Додатки** (§12) — порядок появи посилань, заголовки за пп. 2.3.4.

### 4. Звіт

Вивести `GRILL-REPORT.md` (і коротке резюме в чат) у форматі:

```
# Grill Report — <файл> — <дата ISO>

## Підсумок
Перевірено категорій: N/18. Порушень: X (BLOCKER: a, MAJOR: b, MINOR: c).
Вердикт: PASS | PASS WITH FIXES | FAIL

## Порушення
### [BLOCKER] <короткий заголовок>
- Правило: RULES.md §<розділ> / пп. <номер>
- Знайдено: <цитата/локація у документі (файл:рядок або сторінка)>
- Очікувано: <вимога правила>
- Фікс: <конкретна дія>

### [MAJOR] ...
### [MINOR] ...

## Потребує ручної перевірки
- <пункти, які неможливо перевірити з наявного формату — поля в мм, кеглі тощо>

## Чисті категорії
- §<n> <назва> — без зауважень
```

**Класифікація:**
- **BLOCKER** — відсутній обов’язковий структурний елемент, порушений порядок елементів,
  неправильна нумерація розділів, відсутні обов’язкові посилання, скановані формули.
- **MAJOR** — порушені числові константи (шрифт, поля, інтервали, кеглі), неправильні
  заголовки, неправильне оформлення таблиць/рисунків/формул/переліків.
- **MINOR** — стилістика формулювань заголовків, крапки, регістр, дрібні відступи.

## Принципи
- **Прискіпливість понад увічливість.** Мовчання = пропущена помилка. Кожна категорія
  має або порушення, або явний запис "без зауважень".
- Завжди цитувати **конкретний пункт** правил і **конкретну локацію** в документі.
- Не вигадувати вимог, яких немає в `RULES.md`. Якщо правило неоднозначне — звіритися з
  `pravyla-raw.txt`/`pravyla-proj.pdf` і зацитувати першоджерело.
- Те, що формат не дає перевірити (напр. поля в мм у `.md`), — не "PASS", а в розділ
  "Потребує ручної перевірки".
- Не редагувати документ автоматично без запиту; за згодою користувача — застосувати фікси
  й перезапустити аудит.
