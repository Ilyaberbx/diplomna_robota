# Grill Presentation — аудит презентації проти правил оформлення

Перевіряє файл презентації до захисту проти правил
(`docs/diploma-rules/references/PRESENTATION-RULES.md`) і — за наявності теки роботи —
звіряє зміст слайдів **дослівно** з текстом роботи. Мета — не «переглянути», а
**прискіпливо знайти кожне порушення** й дати конкретний фікс із посиланням на пункт правил.

## Вхід

Аргументи:
- шлях до `.pptx` — типово `thesis/presentation.pptx`;
- тека роботи для звірки — типово `thesis/` (необов'язково).

Якщо презентацію не задано і файл за замовчуванням відсутній — запитати у користувача,
не вгадувати.

## Процедура

### 1. Завантажити еталон
- Прочитати `docs/diploma-rules/references/PRESENTATION-RULES.md` повністю (джерело істини).
- За потреби звіритися з еталонними `docs/diploma-rules/references/sample-presentation-*.pptx`
  щодо норм розкладки.

### 2. Витягнути презентацію
- Відкрити `.pptx` через `python-pptx` (або stdlib `zipfile` для `ppt/presentation.xml`):
  зчитати `sldSz` (співвідношення сторін), кількість слайдів, текст заголовків кожного
  слайда, наявність нумерації, таблиць, зображень і нотаток доповідача.
- Зафіксувати, що **піддається машинній перевірці** (структура, порядок, заголовки,
  16:9, нумерація, наявність таблиці/зображень, дослівність) і що **ні** (візуальна
  якість, розкладка). `PRESENTATION-RULES.md` не задає числових констант кеглів — розміри
  шрифтів поза перевіркою; решту візуального позначати «потребує ручної перевірки».

### 3. Прогнати чек-лист (кожна категорія = окремий прохід)

1. **Формат** — 16:9; кількість слайдів **8–14**; нумерація присутня.
2. **Обов'язкові слайди й порядок** — титульний → мета/задачі → предмет/об'єкт → аналоги →
   діаграми → стек → контрольний приклад → висновки (звірка за текстом заголовків).
3. **Титульний** — тема, виконавець + група, керівник.
4. **Аналоги** — таблиця присутня, є стовпець «Власна розробка».
5. **Діаграми** — кожна на окремому слайді, із заголовком, із зображенням.
6. **Контрольний приклад** — щонайменше один слайд зі скриншотом.
7. **Висновки** — переказують роботу й містять «задачі виконано, мету досягнуто».
8. **Дослівна звірка з роботою** (коли задано теку роботи) — мета/задачі/об'єкт/предмет
   проти `03-vstup.md`, висновки проти `11-zagalni-vysnovky.md`; розбіжність формулювань =
   **BLOCKER**. Без теки роботи — позначити «потребує ручної перевірки».
9. **Анти-патерни** — слайди-«полотна тексту», діаграми без заголовка, нові факти, яких
   немає в роботі.

### 4. Звіт

Вивести `thesis/GRILL-PRESENTATION-REPORT.md` (і коротке резюме в чат) у форматі:

```
# Grill Presentation Report — <файл> — <дата ISO>

## Підсумок
Перевірено категорій: N/9. Порушень: X (BLOCKER: a, MAJOR: b, MINOR: c).
Вердикт: PASS | PASS WITH FIXES | FAIL

## Порушення
### [BLOCKER] <короткий заголовок>
- Правило: PRESENTATION-RULES.md §<розділ>
- Знайдено: <слайд N / цитата>
- Очікувано: <вимога правила>
- Фікс: <конкретна дія>

### [MAJOR] ...
### [MINOR] ...

## Потребує ручної перевірки
- <візуальна якість/розкладка та інше, що формат не дає перевірити>

## Чисті категорії
- §<n> <назва> — без зауважень
```

**Класифікація:**
- **BLOCKER** — відсутній обов'язковий слайд, порушено порядок, неправильне співвідношення
  сторін, дослівна розбіжність із роботою, відсутній обов'язковий змістовий слайд.
- **MAJOR** — немає таблиці аналогів, немає нумерації, кількість слайдів поза 8–14,
  діаграма без заголовка.
- **MINOR** — формулювання заголовків, регістр, дрібні стилістичні відхилення.

## Принципи
- **Прискіпливість понад увічливість.** Мовчання = пропущена помилка. Кожна категорія має
  або порушення, або явний запис «без зауважень».
- Завжди цитувати **конкретний пункт** `PRESENTATION-RULES.md` і **конкретний слайд**.
- Не вигадувати вимог, яких немає в правилах.
- Те, що формат не дає перевірити, — не «PASS», а в розділ «Потребує ручної перевірки».
- Не редагувати презентацію автоматично без запиту; за згодою користувача — застосувати
  фікси (через `/generate-presentation`) і перезапустити аудит.
