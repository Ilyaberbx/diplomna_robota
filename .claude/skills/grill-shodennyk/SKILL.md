# Grill Щоденник — аудит щоденника практики проти правил

Перевіряє **щоденник практики** (`shodennyk.docx`) проти `SHODENNYK-RULES.md` (+ текстові
константи `RULES.md`) і звіряє його зміст із роботою `thesis/`. Мета — не «переглянути», а
**прискіпливо знайти кожне порушення** й дати конкретний фікс із посиланням на пункт правил.

## Вхід

Аргументи:
- тека практики — типово `thesis/practice/` (містить `shodennyk.docx`, `shodennyk-data.md`);
- тека роботи для звірки — типово `thesis/` (необов'язково).

Якщо файлів немає за замовчуванням — запитати у користувача, не вгадувати.

## Процедура

### 1. Завантажити еталони
- Прочитати `docs/diploma-rules/references/SHODENNYK-RULES.md` повністю.
- Прочитати `docs/diploma-rules/RULES.md` як базу текстових констант; за потреби —
  `docs/diploma-rules/pravyla-raw.txt`. Звіритися з еталонною формою
  (`references/Щоденник.docx`, `references/practice/shodennyk-zrazok.pdf`).

### 2. Витягнути документ
- Відкрити `shodennyk.docx` через `python-docx` (`docx.Document(...)`: читати `paragraphs`
  і `tables`) і **додатково** читати `shodennyk-data.md` напряму — точніше для перевірки
  структури й патернів.
- Зафіксувати, що **піддається машинній перевірці** (наявність блоків форми, порядок,
  дослівна звірка, крос-консистентність) і що **ні** (поля в мм, кеглі, візуальна якість
  розкладки) — останнє в «Потребує ручної перевірки».

### 3. Чек-лист щоденника (повнота форми + крос) → `GRILL-SHODENNYK-REPORT.md`

За `SHODENNYK-RULES.md` §5–§6:
1. **Повнота форми** — усі 8 блоків і порядок (§1); титульний блок повний; прибуття/вибуття +
   клітинки М.П.; індивідуальне завдання; Календарний графік — 7 стовпців/тижні 1–4/≥1 рядок
   (§2); робочі записи — датовані діапазони, **покривають період без розривів** (§3); відгук
   підприємства + підпис/М.П.; відгук керівника від університету + висновок; блок оцінки
   (національна + ECTS) — бланки.
2. **Текстові константи** — делеговано до `RULES.md` §1 (A4, TNR 14, інтервал 1,5, поля).
3. **Крос-консистентність** (§6) — ПІБ/група/спеціальність/ОПП == `thesis/00-tytulnyi-arkush.md`;
   підприємство й період узгоджені в межах `shodennyk-data.md`; усі робочі записи ⊆ період;
   роботи Календарного графіку відповідають реальному ходу практики. Без теки роботи —
   позначити «потребує ручної перевірки».

### 4. Звіт

Вивести файл `thesis/practice/GRILL-SHODENNYK-REPORT.md` (і коротке зведене резюме вердикту
в чат) у форматі:

```
# Grill Щоденник Report — <файл> — <дата ISO>

## Підсумок
Перевірено категорій: N. Порушень: X (BLOCKER: a, MAJOR: b, MINOR: c).
Вердикт: PASS | PASS WITH FIXES | FAIL

## Порушення
### [BLOCKER] <короткий заголовок>
- Правило: <SHODENNYK-RULES.md|RULES.md> §<розділ>
- Знайдено: <файл:рядок / блок .docx / цитата>
- Очікувано: <вимога правила>
- Фікс: <конкретна дія>

### [MAJOR] ...
### [MINOR] ...

## Потребує ручної перевірки
- <поля в мм, кеглі, візуальна якість — формат не дає перевірити>

## Чисті категорії
- §<n> <назва> — без зауважень
```

**Класифікація:**
- **BLOCKER** — відсутній обов'язковий блок щоденника; порушено порядок; крос-розбіжність
  ПІБ/підприємства/періоду між щоденником і `thesis/`; робочі записи з розривами або поза
  періодом.
- **MAJOR** — порушені текстові константи `RULES.md`; Календарний графік без потрібних
  стовпців/тижнів; неповний титульний блок.
- **MINOR** — формулювання заголовків, регістр, дрібні стилістичні відхилення.

## Принципи
- **Прискіпливість понад увічливість.** Мовчання = пропущена помилка. Кожна категорія має
  або порушення, або явний запис «без зауважень».
- Завжди цитувати **конкретний пункт** правил і **конкретну локацію** (файл:рядок або
  блок/таблиця в `.docx`).
- Не вигадувати вимог, яких немає в правилах.
- Те, що формат не дає перевірити, — не «PASS», а в розділ «Потребує ручної перевірки».
- Не редагувати документ автоматично без запиту; за згодою користувача — застосувати фікси
  (через `/generate-shodennyk`) і перезапустити аудит.
