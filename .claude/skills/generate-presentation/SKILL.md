# Generate Presentation — генерація презентації до захисту за правилами «Одеської політехніки»

Збирає **файл `.pptx`** презентації до захисту кваліфікаційної роботи, який **за побудовою**
відповідає правилам оформлення презентації й повторює структуру та стиль захищених
еталонних презентацій. Зміст береться з **уже згенерованої роботи** в `thesis/` — слайди
візуалізують текст, а не вводять нового. Мета — не «накидати слайди», а видати презентацію,
що **проходить `/grill-presentation` без BLOCKER/MAJOR**.

## Вхід

Аргументи (усі необов'язкові):
- тека роботи — типово `thesis/`;
- шлях виводу — типово `thesis/presentation.pptx`.

Якщо теки роботи немає або зміст неоднозначний — **запитати у користувача**, не вгадувати.
Презентація без вихідної роботи не генерується (нема звідки брати verbatim-зміст) — у такому
разі попросити спершу згенерувати роботу через `/generate-diplom`.

## Джерела істини (читати перед генерацією)

1. **`docs/diploma-rules/references/PRESENTATION-RULES.md`** — тверді правила структури
   слайдів, формат-константи (16:9, 8–14 слайдів, нумерація) і чек-ліст. Не рекомендації.
2. **`docs/diploma-rules/references/sample-presentation-1.pptx` / `sample-presentation-2.pptx`**
   — візуальний еталон (розкладка, таблиця аналогів, слайди діаграм і контрольного прикладу).
   `sample-presentation-2.pptx` також слугує **шаблоном стилю** (див. процедуру).
3. **Тека роботи `thesis/`** — джерело змісту згідно з картою нижче.

За розбіжності `PRESENTATION-RULES.md` (як оформити слайди) має перевагу.

## Карта «робота → слайди»

| Слайд | Джерело в `thesis/` |
|---|---|
| Титульний | `00-tytulnyi-arkush.md` (тема, ПІБ + група, керівник, місто–рік) |
| Мета і задачі | `03-vstup.md` — **дослівно** |
| Предмет та об'єкт | `03-vstup.md` — **дослівно** |
| Аналіз аналогів | `04-rozdil-1.md` → порівняльна таблиця зі стовпцем «Власна розробка» |
| Use-case / архітектура / схема БД | `figures/1-4.png`, `figures/4-1.png`, `figures/4-2.png` |
| Стек технологій | `08-rozdil-5.md` |
| Контрольний приклад | `figures/7-*.png` (розділ 7 — експлуатація), один скриншот на слайд |
| Загальні висновки | `11-zagalni-vysnovky.md` — **дослівно**, із підсумком «задачі виконано, мету досягнуто» |

Імена рисунків `<розділ>-<n>.png` = «рис. `<розділ>.<n>`», тож контрольний приклад — це `7-*`.
Якщо потрібного PNG діаграми немає — згенерувати наявним скриптом `thesis/render_diagrams.sh`.

## Процедура

### 1. Підготовка
- Прочитати `PRESENTATION-RULES.md` повністю.
- Прочитати джерела з теки роботи за картою; **витягнути дослівно** мету, задачі, об'єкт,
  предмет (з `03-vstup.md`) і висновки (з `11-zagalni-vysnovky.md`); зібрати таблицю аналогів
  з розділу 1 і перелік стека з розділу 5; визначити шляхи рисунків.
- Звірити склад слайдів із обов'язковою послідовністю `PRESENTATION-RULES.md`. Відсутній
  обов'язковий вміст у роботі — узгодити з користувачем, не вигадувати.

### 2. Інструмент
- Переконатися, що в `thesis/.venv` встановлено `python-pptx`; якщо ні — встановити в цей venv.

### 3. Збірка `.pptx` (через відтворюваний скрипт)
Написати `thesis/build_pptx.py` (у стилі наявного `thesis/build_pdf.py`), який:
- відкриває `docs/diploma-rules/references/sample-presentation-2.pptx` як **шаблон**;
- **видаляє його контентні слайди** через `prs.slides._sldIdLst` (зберігаючи тему, майстри,
  розкладки, шрифти й нумерацію), потім додає наші слайди за картою;
- титульний (тема/виконавець+група/керівник), мета+задачі (марковано, дослівно),
  об'єкт+предмет (дослівно), аналоги (`add_table`, стовпець «Власна розробка»), слайди
  діаграм (`add_picture`, з заголовком, по одній на слайд), стек, по одному слайду
  контрольного прикладу на кожен `7-*.png`, висновки;
- забезпечує співвідношення **16:9** і **нумерацію** слайдів;
- виводить `thesis/presentation.pptx`.

Запустити скрипт і отримати файл.

### 4. Доповідь у нотатках доповідача
Для кожного слайда заповнити нотатки (`slide.notes_slide.notes_text_frame`) текстом
доповіді на **~5–7 хв** загалом, виведеним з тексту роботи. **Цей текст — проза**, тож
прогнати його через скіл **`humanizer`** (прибрати AI-ознаки). Нотатки гуманізувати, а
**вміст слайдів — ні**: мета/задачі/об'єкт/предмет/висновки на слайдах лишаються дослівними
з роботи (інакше зламається verbatim-перевірка в `/grill-presentation`).

### 5. Самоперевірка (обов'язково)
Прогнати результат через **`/grill-presentation thesis/presentation.pptx thesis/`**. Якщо
звіт містить BLOCKER або MAJOR — виправити збірку й перегенерувати, доки вердикт не стане
`PASS` / `PASS WITH FIXES` без BLOCKER/MAJOR. Лише тоді повідомляти готовність.

## Принципи
- **Правила — не побажання.** Презентація не «готова», доки `/grill-presentation` не
  підтвердив відсутність BLOCKER/MAJOR.
- **Слайд візуалізує роботу.** Мета/задачі/об'єкт/предмет/висновки — дослівно з роботи;
  діаграми й скриншоти — ті самі рисунки, без створення нових.
- **Еталон — для розкладки/стилю, `PRESENTATION-RULES.md` — для структури.** Не копіювати
  текст еталонних презентацій (інша тема) — наслідувати каркас і вигляд.
- Не вигадувати фактів про продукт: відсутній матеріал позначати `[ПОТРЕБУЄ ДАНИХ: …]`,
  а не фабрикувати.
- Уточнювати неоднозначне (тека роботи, склад слайдів) до генерації, а не після.
