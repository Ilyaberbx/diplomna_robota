# Правила оформлення презентації до захисту

Конспект правил оформлення **презентації** для захисту кваліфікаційної роботи
бакалавра Національного університету «Одеська політехніка». Нормалізований із двох
захищених еталонних презентацій (`sample-presentation-1.pptx`,
`sample-presentation-2.pptx`) — аналог того, чим є [`../RULES.md`](../RULES.md) для
текстової частини.

> **Зв'язок із текстом роботи.** Презентація не вводить нового змісту — вона візуалізує
> вже написане в роботі. Мета, задачі, об'єкт, предмет і висновки беруться **дослівно**
> зі Вступу та Загальних висновків роботи, оформленої за [`../RULES.md`](../RULES.md).
> Діаграми та скриншоти — ті самі рисунки, що й у роботі.

## Призначення

Документ описує структуру, обов'язковий склад слайдів і правила вмісту презентації.
Використовується скілом `/generate-diplom` як зразок для генерації презентації разом з
еталонними `.pptx` у цій теці.

## Формат-константи

| Параметр | Значення |
|---|---|
| Співвідношення сторін | **16:9** (обидва еталони; `screen16x9`) |
| Кількість слайдів | **8–14**, типово **10–12** |
| Мова | українська |
| Нумерація слайдів | номер у кутку кожного слайда (крім титульного) |
| Щільність | **одна думка / одна діаграма на слайд** |
| Заголовок | тема роботи **дослівно** як у титульному аркуші |

## Обов'язкова послідовність слайдів

Канонічний порядок. Праворуч — звідки в роботі береться вміст.

| # | Слайд | Вміст | Джерело в роботі |
|---|---|---|---|
| 1 | **Титульний** | «КВАЛІФІКАЦІЙНА РОБОТА БАКАЛАВРА», тема, «Виконав: ст. гр. …», «Керівник: …» | Титульний аркуш |
| 2 | **Мета і задачі** | Формулювання мети + марковані задачі | Вступ (дослівно) |
| 3 | **Предмет та об'єкт** | Об'єкт дослідження + предмет дослідження | Вступ (дослівно) |
| 4 | **Аналіз аналогів** | Порівняльна таблиця: характеристики × конкуренти + стовпець «Власна розробка» | Розділ аналізу предметної області |
| 5 | **Діаграма варіантів використання** | Use-case діаграма (тільки зображення + заголовок) | Розділ вимог |
| 6 | **Діаграма послідовності** *(за потреби)* | Sequence-діаграма ключового сценарію | Розділ проєктування |
| 7 | **Схема бази даних** | ER / схема БД (тільки зображення + заголовок) | Розділ проєктування |
| 8 | **Стек технологій** | Перелік / схема використаних технологій | Розділ реалізації |
| 9–11 | **Контрольний приклад** | Скриншоти ключових екранів: авторизація + 2–3 основні функції (по одному екрану на слайд) | Розділ експлуатації |
| 12 | **Загальні висновки** | Маркований підсумок: що зроблено + «усі задачі виконано, мету досягнуто» | Загальні висновки (дослівно) |

Слайди 6 і деякі діаграми — опційні залежно від теми; слайди 1–4, стек, контрольний
приклад і висновки — обов'язкові завжди.

## Правила вмісту

1. **Мета, задачі, об'єкт, предмет** на слайдах мають збігатися зі Вступом роботи
   **слово в слово**. Розбіжність формулювань — порушення.
2. **Задачі** на слайді 2 — той самий маркований список, що й у Вступі (без скорочення
   кількості пунктів).
3. **Висновки** (останній слайд) переказують Загальні висновки роботи й завершуються
   твердженням, що **поставлені задачі виконано, а мету роботи досягнуто**.
4. **Діаграми та скриншоти** — ті самі рисунки, що в роботі; не створювати нових.
5. **Таблиця аналогів** — формат «характеристика × продукт», останній стовпець завжди
   «Власна розробка», у рядках — `+` / `-` / `+-` та рядок «Ціна» і «Найкраще підходить для».
6. **Один заголовок на слайд**; слайди з діаграмами/скриншотами несуть лише заголовок і
   зображення, без абзаців тексту.

## Чого уникати

- Слайди-«полотна тексту» (суцільні абзаци замість тез чи зображення).
- Мета / задачі / об'єкт / предмет, що **не збігаються** з текстом роботи.
- Діаграми та скриншоти **без заголовка**.
- Нові факти на слайдах, яких немає в роботі.
- Порушення 16:9 або відсутність нумерації слайдів.

- [ ] 8–14 слайдів, нумерація присутня.
- [ ] Титульний: тема, виконавець (група), керівник.
- [ ] Мета і задачі — дослівно зі Вступу.
- [ ] Об'єкт і предмет — дослівно зі Вступу.
- [ ] Таблиця аналогів зі стовпцем «Власна розробка».
- [ ] Діаграми (use-case / БД) — по одній на слайд, із заголовком.
- [ ] Слайд стека технологій присутній.
- [ ] Контрольний приклад: скриншоти ключових екранів.
- [ ] Висновки переказують Загальні висновки + «задачі виконано, мету досягнуто».
